# コア機能

タイルマップ編集がマップエディタの根幹です。グリッドベースのキャンバス上にタイルを配置・編集する仕組みで、最低限必要なのはタイルパレットからの選択、キャンバスへの描画、消去の3つです。
描画ツールとしては、ペン（1マス単位）、矩形塗りつぶし、バケツ（フラッドフィル）、矩形選択＆コピー/ペーストあたりが基本セットになります。RPGツクールでは「影ペン」や「オートタイル」もありますが、これらは優先度を分けて考えた方がいいです。
レイヤー構造も重要です。RPGツクールでは地面・装飾・上層の複数レイヤーがあり、キャラクターの上に木の葉を被せるような表現ができます。最低2レイヤー（地面＋オブジェクト）は欲しいところです。

# タイルセット管理

タイルセット（チップセット）の読み込みと管理機能が必要です。具体的には、画像ファイルからタイルセットをインポートする機能、タイルサイズの設定（16×16、32×32、48×48など）、各タイルへの通行判定（passability）の設定、そしてオートタイルの定義です。
オートタイルは隣接タイルに応じて自動的に見た目が変わる仕組みで（水辺や崖など）、実装コストは高いですが体験を大きく向上させます。

# マップ属性・設定

マップ単体に紐づく設定として、マップ名、マップサイズ（幅×高さをタイル数で指定）、BGMの設定、エンカウント設定（RPG用途の場合）、スクロールタイプ（ループの有無）などがあります。

# ナビゲーション・操作性

快適に編集するための機能も重要です。ズームイン/アウト、パン（スクロール）、グリッド表示の切り替え、ミニマップ（全体俯瞰）、Undo/Redo。特にUndo/Redoは開発初期から設計に組み込むべきです。後から追加すると設計が大きく崩れます。

# データ管理

マップデータの保存/読み込み形式を決める必要があります。JSON形式が扱いやすいでしょう。マップの一覧管理（ツリー構造でワールドマップ→町→建物内部のような階層）、マップ間の接続情報の管理も考慮が必要です。

# イベントとの連携

既にイベントエディタがあるとのことなので、マップ上にイベントを配置する機能が接続点になります。マップ上の座標を指定してイベントを紐づけ、マップエディタ上でイベントの存在をアイコン等で可視化する形です。

# 優先度の整理案

実装を段階的に進めるなら、こんな分け方が考えられます。

- Phase 1（MVP） — タイルパレット＋ペン描画、単一レイヤー、マップサイズ設定、保存/読込、Undo/Redo、ズーム/パン
- Phase 2 — 複数レイヤー、矩形描画・バケツツール、コピー/ペースト、グリッド表示切替、タイル通行判定設定
- Phase 3 — オートタイル、マップツリー管理、イベント配置連携、ミニマップ、BGM等の属性設定
