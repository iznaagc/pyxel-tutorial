## GUIライブラリ選定

### 調査結果サマリ

| ライブラリ | 日本語 | ツリー | テキスト編集 | ライセンス | 配布サイズ | 評価 |
|-----------|--------|--------|------------|----------|-----------|------|
| **PySide6** | ◎ | ◎ QTreeWidget | ◎ QTextEdit | LGPL（商用無料） | 150-300MB | **推奨** |
| **PyQt6** | ◎ | ◎ QTreeWidget | ◎ QTextEdit | GPL/商用有料 | 150-300MB | ライセンス問題 |
| wxPython | ◎ | ○ TreeCtrl | ○ TextCtrl | wxWindows(LGPL相当) | 15-35MB | 次点 |
| Dear PyGui | △ 日本語バグ | × 独自実装必要 | × なし | MIT | 50-100MB | 不適 |
| customtkinter | △ IME問題 | × なし | △ 基本的 | MIT | 30-40MB | 不適 |
| tkinter | △ IME問題 | △ 手動構築 | △ 基本的 | Python | 25-35MB | 不適 |
| Kivy | △ | △ | △ | MIT | 80-120MB | モバイル向け |
| PySimpleGUI | - | - | - | - | - | 開発終了 |

### 推奨: PySide6

**選定理由:**
- **日本語テキスト**: IME含めて完全対応（Qt のネイティブ対応）
- **ツリーウィジェット**: QTreeWidget でカテゴリ別階層表示が標準機能
- **テキスト編集**: QTextEdit は構文ハイライト対応の本格エディタ
- **ライセンス**: LGPL なので商用利用でもソース公開不要（PyQt6 は GPL で制約大）
- **メンテナンス**: The Qt Company が公式メンテナンス、2026年も活発にリリース
- **拡張性**: 将来イベントエディタ・マップエディタに発展させる基盤として最適

**トレードオフ:**
- 配布サイズが大きい（150-300MB）→ 開発ツールなので許容範囲
- 起動が若干遅い（1-2秒）→ エディタなので問題なし

**次点: wxPython**
- 配布サイズ最小（15-35MB）、Windows ネイティブ外観
- ウィジェットが Qt ほど高機能ではない

## Phase 3: テキストファイル分割

### 目的

1ファイル集約（demo_text.json）からシーン別分割へ移行し、管理性を向上させる。

### ファイル構成

```
data/text/
├── _common.json          ← 共通テキスト（UI文言、システムメッセージ等）
├── demo.json             ← デモシーン用テキスト（現 demo_text.json をリネーム）
├── chapter01.json        ← 将来のチャプター別ファイル（例）
└── chapter02.json
```

### JSONスキーマ変更

各ファイルに `file_id` を追加し、ID衝突を検出可能にする:

```json
{
  "version": 1,
  "file_id": "demo",
  "messages": { ... },
  "selections": { ... },
  "telops": { ... }
}
```

### コンパイラ変更

- `data/text/` 内の全 `.json` を読み込み
- 全ファイルの messages / selections / telops をマージ
- ID重複チェック（衝突時はエラー + どのファイル由来か表示）
- 出力は従来通り 1つの `compiled/text_all.bin`

### TextManager 変更

- `demo_text.bin` → `text_all.bin` に読み込み先変更
- API は変更なし（get_messages, get_selection, get_telop）

```
│   msg_c..│ ┌────────────────┐ │ │こんにちは！    │    │
│   msg_m..│ │こんにちは！      │ │ │メッセージウィン│    │

```

### 3ペイン構成

| ペイン | ウィジェット | 役割 |
|--------|-----------|------|
| 左: ファイルツリー | QTreeWidget | ファイル→カテゴリ→ID の3階層表示 |
| 中央: テキスト編集 | QTextEdit + QLineEdit | 選択中IDのテキスト・名前・オプション編集 |
| 右: プレビュー | QWidget (カスタム描画) | ゲームUIコンポーネントで表示確認 |

### 機能一覧

#### 基本操作
- ファイルツリーでテキストID選択 → 中央に編集フォーム表示
- テキスト編集 → リアルタイムプレビュー更新
- Ctrl+S: JSONファイル保存
- Ctrl+Z / Ctrl+Y: Undo/Redo

#### ファイルツリー
- ファイル別 → カテゴリ別（Messages/Selections/Telops）→ ID の3階層
- 右クリック: 新規ID追加 / 削除 / リネーム / コピー
- ドラッグ&ドロップ: ファイル間移動

#### テキスト編集エリア
- Messages: テキスト(QTextEdit) + 名前(QLineEdit) + 自動送りチェック + ページ送り
- Selections: アイテムリスト編集(QListWidget) + cancel_index + semi_transparent
- Telops: 行リスト編集(QTextEdit) + scroll_speed(QDoubleSpinBox)

#### プレビューパネル
- 編集内容をリアルタイムでゲーム風に描画
- 方式検討: (A) Pyxel をサブプロセスで起動して画像転送、(B) QPainter で再現描画
- → **(B) QPainter 再現描画を推奨**（レスポンスが良く実装がシンプル）

#### ツールバー / メニュー
- File: 新規ファイル作成 / 保存 / 全保存
- Edit: Undo / Redo / 検索(Ctrl+F)
- Tools: コンパイル(F5) / ゲーム起動(F6) / バリデーション

### プレビュー方式の比較

| 方式 | メリット | デメリット |
|------|---------|----------|
| (A) Pyxel サブプロセス | ゲームと完全同一の表示 | プロセス間通信が複雑、遅延あり |
| (B) QPainter 再現描画 | 高速、PySide6内で完結 | ゲーム本体と描画差異の可能性 |
| (C) Pyxel 画面キャプチャ→QPixmap | 見た目は完全一致 | 毎回キャプチャで遅い |

**推奨: (B) QPainter 再現描画**
- フォント読み込み（BDF/TTF）→ QPainter で文字描画
- ウィンドウ枠は矩形描画で再現
- Pyxel パレットカラーを使用して色味を合わせる
- 差異が出ても「プレビューはあくまで参考」と割り切れる
