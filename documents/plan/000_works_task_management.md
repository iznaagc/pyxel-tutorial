## 共通作業の詳細手順

### 共通1. gh CLI のインストール

```powershell
# winget（推奨）
winget install GitHub.cli

# または scoop
scoop install gh
```

インストール後、**新しいターミナルを開き直す**こと（PATHの反映のため）。

### 共通2. GitHub認証

```bash
gh auth login
```

対話形式で以下を選択:
1. `GitHub.com`
2. `HTTPS`
3. `Login with a web browser`（ブラウザが開く → GitHubにログイン → デバイスコードを入力）

確認:
```bash
gh auth status
# → 「Logged in to github.com account iznaagc」と表示されればOK
```

### 共通3. GitHub PAT の発行

GitHub MCP サーバーが GitHub API にアクセスするために必要。

1. https://github.com/settings/tokens?type=beta にアクセス
2. 「Generate new token」をクリック
3. 設定:
   - **Token name**: `pyxel-tutorial-mcp`
   - **Expiration**: 任意（90日推奨）
   - **Repository access**: `Only select repositories` → `iznaagc/pyxel-tutorial`
   - **Permissions**:
     - Issues: Read and write
     - Pull requests: Read and write
     - Contents: Read（コード参照用）
     - Metadata: Read（必須）
4. 「Generate token」をクリックし、表示されたトークンを控える

**注意**: トークンは一度しか表示されない。安全な場所に保管すること。

### 共通4. GitHubリポジトリにラベルを作成

```bash
gh label create "task"        --description "実装タスク"      --color "0075ca"
gh label create "bug"         --description "バグ報告"        --color "d73a4a"
gh label create "enhancement" --description "改善提案"        --color "a2eeef"
gh label create "question"    --description "相談・議論"      --color "d876e3"
gh label create "blocked"     --description "着手不可（依存待ち）" --color "e4e669"
```

※ デフォルトで存在するラベルと重複する場合はスキップでOK。

### 共通5. AGENT.md にタスク管理ルールを追記

`AGENT.md` に以下のセクションを追加する（詳細は本ドキュメント参照）:
- 作業開始前にIssue一覧を確認すること
- 着手時にIssueコメントで宣言すること
- ブランチ命名規則に従うこと

## 個別作業の詳細手順

### 個別1. MCP サーバーの設定

各AIツールの設定ファイルに GitHub MCP サーバーを登録する。

#### Claude Code の場合

プロジェクトルートの `.mcp.json` に追記:

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "<発行したPATをここに設定>"
      }
    }
  }
}
```

**注意**: `.mcp.json` にPATを直書きする場合、`.gitignore` に追加してリポジトリにコミットしないこと。
代替として環境変数を使う方法:

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_PAT}"
      }
    }
  }
}
```

この場合、システム環境変数 `GITHUB_PAT` にトークンを設定しておく。

#### Cursor の場合

`.cursor/mcp.json` に同様の設定を追加する。

#### その他のAI

MCP非対応のAIは `gh` CLI をフォールバックとして使用する。
`gh` の認証トークン（`~/.config/gh/hosts.yml`）は同一マシン上の全AIで共有される。

### 個別2. 接続テスト

MCP サーバー経由またはgh CLI で以下を実行し、疎通を確認:

```bash
# gh CLI での確認
gh issue list --repo iznaagc/pyxel-tutorial --state open
```

MCP経由の場合は、AIのチャットで「このリポジトリのIssue一覧を取得して」と指示して確認。

#### Codex での補足

- Codex では `.mcp.json` や `GITHUB_PAT` の変更が**既存セッションに即時反映されない**場合がある
- 認証やMCP設定を変更した後は、**Codex セッションを再起動してから再テスト**する
- 起動後も GitHub MCP が見えない場合は、まず `tools/check_github_task_env.ps1` を実行して `gh` フォールバックが使える状態か確認する
- Codex 本体のプラグイン同期やGitHubコネクタが不安定な場合でも、`gh` CLI が有効なら Issue/PR ベースの運用は継続できる

## GitHub Issues の運用ルール

### Issueの作成

```bash
gh issue create \
  --title "タスクのタイトル" \
  --label "task" \
  --body "$(cat <<'EOF'
## 概要
何をするか

## 背景・目的
なぜ必要か

## 影響範囲
変更対象のファイルやモジュール

## 依存関係
- 依存: #Issue番号（先にこれが完了する必要がある）
- ブロック: #Issue番号（このタスクが完了しないと着手できないもの）

## 備考
他タスクへの影響や注意事項
EOF
)"
```

### 着手宣言

```bash
gh issue comment <番号> --body "🤖 **Claude Code** が着手します（ブランチ: task/<番号>-xxx）"
```

### ブランチ命名規則

- 形式: `task/<Issue番号>-簡潔な説明`
- 例: `task/15-add-save-feature`
- mainブランチへの直接コミットは禁止

### Pull Request

```bash
gh pr create \
  --title "タスクのタイトル" \
  --body "$(cat <<'EOF'
## Summary
- 変更内容の要約

## Related Issue
Closes #Issue番号

## テスト・確認
- [ ] 動作確認済み
- [ ] スクリーンショット撮影済み

🤖 Generated by **AI名**
EOF
)"
```

`Closes #番号` でPRマージ時にIssueが自動クローズされる。

## 並列作業のルール

### 作業開始前の確認

AIは新規作業を開始する前に、必ず以下を確認する:

```bash
gh issue list --state open
gh pr list --state open
```

- 他のAIが着手宣言済みのIssueは避ける
- 着手可能でも他の作業中タスクとファイルが重なる場合は人間に相談する

### コンフリクト防止

- **影響範囲の明示**: Issue作成時に変更対象ファイルを記載する
- **ロック宣言**: 共有ファイルを編集する場合、Issueコメントで宣言する
- **小さなコミット単位**: 機能単位で細かくコミットする

### コンテキスト制限時のハンドオフ

AIが制限に近づいた場合:

1. 現在の進捗をコミット＆プッシュする
2. Issueにコメントで進捗を記録する:

```bash
gh issue comment <番号> --body "$(cat <<'EOF'
## ハンドオフ（AI名 → 次のAI）

### 完了した作業
- xxx

### 未完了の作業
- xxx

### 注意事項
- xxx

### ブランチ
`task/<番号>-xxx` の最新コミット: <ハッシュ>
EOF
)"
```
